# 后端开发规范

本规范适用于 `backend/`、`backend/alembic/` 及涉及数据库的脚本。后端的首要目标是保证业务口径、用户隔离和只读查询边界，而不只是让接口返回数据。

## 1. 架构边界

采用模块化单体，按职责分包；不为了分层增加空转发服务、通用 CRUD 基类或微服务。

| 位置 | 职责 |
| --- | --- |
| `app/main.py` | 应用工厂、路由注册、中间件、异常到 HTTP 的映射；不编写业务流程和 SQL |
| `app/api/` | 按功能划分的 HTTP 路由、身份依赖、请求模型、Cookie 和 NDJSON 编码 |
| `app/services/` | 问数用例编排、执行状态与取消协调；不接收 Request、Response 或 Depends |
| `app/repositories/` | 应用数据读写、所有权过滤、事务和数据库锁；不返回 HTTP 响应 |
| `app/contracts.py` | 问数上下文、执行记录、查询结果和流事件的内部类型契约 |
| `app/presentation/` | 确定性摘要、分析过程与 CSV；不访问数据库或模型 |
| `app/query/` | 编译与 AST 校验、只读执行、日期与指标计算、SQL 展示分别维护 |
| `app/semantic.py` | 指标、逻辑维度、查询计划及业务组合约束 |
| `app/llm.py`、`app/audio.py` | 外部模型协议、结构校验、错误归一化及有限重试 |
| `app/retrieval.py` | 业务目录同步与召回；不决定 SQL 或参与金额计算 |
| `app/db.py`、`app/schema.py` | 连接池与统一 SQLAlchemy 元数据 |
| `app/catalog.py` | 领域表、字段和业务说明的目录来源 |

依赖方向是 API → 服务/仓储 → 语义契约与基础设施。简单 CRUD 可以直接调用仓储；跨步骤、跨事务用例放入服务。仓储、查询及展示模块不得反向导入 API 或 `main.py`。公共类型放在独立契约模块，不通过服务模块互相导入。

`app.query` 的包入口仅导出明确的公共函数，不保留已替代实现。脚本导入实际服务或仓储，不通过 ASGI 入口取工具函数。保留统一表元数据，避免为了目录对称而拆出互相依赖的表模块。

模型不获得数据库账号、API Key 或任意 SQL 执行能力。认证行为、接口契约和业务口径不能借结构重构顺带修改。

## 2. 接口与 Schema

- 请求体使用 Pydantic 模型，设置长度、枚举、数值范围和必要的规范化校验。
- 返回浏览器的数据只包含前端需要的安全字段。
- 请求模型放在 `api/schemas.py`，不传入仓储；使用明确参数或内部契约类型。问数服务输出结构化事件，由 API 编码成 NDJSON。
- 结构重构前后比较 OpenAPI，并核对历史消息、反馈和导出的消费路径。内部类型不得强制把历史缺失字段补成零值或空结果。
- 修改返回结构前先查找所有前端消费点和历史持久化数据。
- 错误响应使用稳定、可展示的中文 `detail`；不得透传上游原始错误、密钥或连接信息。
- PATCH 只更新显式提交的字段，未提交字段保持原值。
- 时间使用明确时区；持久化和传输优先使用 UTC，展示转换交给前端。

## 3. 用户隔离与权限

- 会话、消息、收藏、工作台设置、常见问题和反馈操作必须按当前用户过滤。
- 读取、修改、删除和导出都要检查资源所有权，不能只在列表接口过滤。
- 删除接口应对不存在或不属于当前用户的资源返回安全结果，不泄露其他用户资源是否存在。
- 保持 Cookie、Origin 校验和已有登录限流策略，除非需求明确要求变更。

## 4. 问数与 SQL 安全

- 模型只生成受约束的查询计划，SQL 必须由程序编译。
- 所有筛选值使用绑定参数，不拼接用户输入。
- 保持 SQLGlot AST 校验、允许表/schema/函数限制和单条 SELECT 限制。
- 查询使用 analyst 只读连接、READ ONLY 事务、statement timeout 和结果上限。
- 新增指标时必须声明粒度、公式、允许维度、时间行为和比较逻辑，并增加独立数值核对。
- 百分比指标按业务公式聚合，不能平均分组百分比。
- 不跨不兼容事实粒度直接 JOIN；需要时先分别聚合或使用既有 UNION ALL 结构。

## 5. NDJSON 流

- 只发送真实可解释的阶段状态，不暴露或伪造模型内部思维链。
- 每个事件是一行完整 JSON，并以换行分隔。
- `status` 用于阶段，`analysis` 用于可审计步骤，`result` 是唯一最终消息。
- 成功、业务澄清、不支持、验证错误、系统错误和取消都必须持久化一致的消息状态。
- 请求作用域负责 advisory lock 和连接清理；必须覆盖响应未开始迭代、正常完成、断连、取消、准备失败和发送失败。
- 锁使用独立连接池，不在等待模型时占用应用事务池；会话锁取得后结束获取锁的事务。解锁失败时销毁物理连接，不能把潜在持锁连接放回池中。
- 终态写入和本地“已保存”标记在取消屏蔽区内完成。消息、审计、成功问题统计和追问上下文在同一事务提交；失败/取消不推进成功上下文。
- 对已成功提交的结果不因后续断连改写为取消。尚未提交的半成品不能带着 success 状态进入历史记录。
- 数据库故障时不能承诺持久化成功；记录安全错误类型与消息 ID，返回通用错误，并仍然释放资源。
- 最终结果中的文字、图表数据、汇总值和执行审计必须来自同一次查询结果。

## 6. 数据库与迁移

- Schema 变更必须通过 Alembic，不在启动代码中临时修改生产表。
- 已发布迁移保持不可变；新增变更创建新版本。
- 新迁移必须携带本版本冻结的表、字段和注释常量，不导入运行时业务目录、设置默认值或模型定义。`alembic/env.py` 可加载当前 metadata 用于差异比较。
- 历史 `0002`、`0003`、`0004` 仍引用运行时目录，是已知迁移债务。本轮结构重构不改写历史文件；以后增加目录字段必须核对从空库重放，不能仅验证已有数据库升级。
- 新增领域表或列时同步更新 `app/catalog.py` 的中文业务说明和数据库 COMMENT。
- 仓储对一次原子读写拥有事务边界；需要组合的操作在同一连接内完成，不让每个子步骤各自提交。不得在事务中等待外部模型。
- 初始化和迁移不得覆盖已有业务数据。迁移、授权和演示种子仍为现有容器启动流程；扩展为多实例部署前需拆出独立迁移任务，不把部署行为改动混入普通代码移动。
- 数据导入前检查目标是否已有数据，并核对逐表记录数。
- 不运行 `docker compose down -v`，除非用户明确要求删除整个容器数据库。

## 7. Python 实现

- 使用明确的函数和 Pydantic/SQLAlchemy 类型边界，避免宽泛字典在多层间无约束传递。
- 异步请求路径的 `async def` 中不直接执行同步数据库连接、SQL、事务提交或解锁；服务使用 AnyIO 工作线程，HTTP 适配层可使用 Starlette 线程池。同步路由由框架调度到线程池。
- 获取连接、使用连接、提交/回滚作为完整同步工作单元。不得在线程间并发使用同一个 SQLAlchemy Connection。
- 不强行中断正在执行的同步 SQL；等待数据库完成或 statement timeout 后清理。外部模型等待可直接取消。
- 只捕获能够处理的异常。未知异常记录类型和追踪标识，对浏览器返回通用安全提示。
- 重试仅用于明确的瞬态外部错误；取消和业务校验错误不得重试。
- 日志不得包含密码、Cookie、完整 token、API Key 或不必要的用户敏感内容。

## 8. 验证流程

- `tests/unit/`：纯计算、服务状态、线程边界、清理失败与无需数据库的 HTTP 行为；不调用真实模型。
- `tests/integration/`：经确认的本地 PostgreSQL、账号隔离、SQL 权限、金额独立核对、历史结果和真实 HTTP 断连。仅在 `TEST_DATABASE=1` 时启用。
- 集成测试先注册清理，再创建测试账号；清理必须按本轮生成的明确 ID，setup 失败也执行。不得批量清空业务数据或删除不明测试记录。
- 流式修改至少覆盖成功、澄清、不支持、业务校验失败、系统失败、取消和锁释放；真实断连使用本地 HTTP 服务，模型边界可以替换为受控测试实现。

1. 查看 `git status`；运行数据库测试前确认连接目标不是生产环境，不输出 `.env` 的值。
2. 运行 `PYTHONPATH=backend .venv/bin/pytest backend/tests -q`。只运行单元测试可使用 `PYTHONPATH=backend .venv/bin/pytest backend/tests/unit -q`。
3. 涉及数据库、权限、迁移、流式持久化或数值计算时，运行 `TEST_DATABASE=1 PYTHONPATH=backend .venv/bin/pytest backend/tests -q`。
4. 接口重构核对状态码、响应结构和 OpenAPI；流式重构检查最终消息与审计一致，并确认取消后同用户可再次请求。
5. 真实模型评估会消耗额度，只在任务明确需要时运行；模型替身通过不代表真实自然语言理解已经验证。
6. 交付说明写明测试数量、数据库环境、警告和未验证项。Python 文件使用一致格式与显式导入，不借格式化改动无关模块。

不要为了通过测试降低用户隔离、SQL 校验、只读权限、超时或结果限制。
