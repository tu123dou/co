# 后端开发规范

本规范适用于 `backend/`、`backend/alembic/` 及涉及数据库的脚本。后端的首要目标是保证业务口径、用户隔离和只读查询边界，而不只是让接口返回数据。

## 1. 架构边界

- `app/main.py` 负责 HTTP、鉴权、所有权校验和流式响应编排。
- `app/semantic.py` 负责版本化指标字典和查询计划 Schema。
- `app/query.py` 负责受控 SQL 编译、校验和数值计算。
- `app/llm.py` 负责模型调用、结构校验和有限重试。
- `app/retrieval.py` 只增强业务语义召回，不参与金额计算或直接决定 SQL。
- `app/catalog.py` 是领域表、字段和业务说明的目录来源。
- 不把数据库账号、API Key 或任意 SQL 执行能力交给模型。

## 2. 接口与 Schema

- 请求体使用 Pydantic 模型，设置长度、枚举、数值范围和必要的规范化校验。
- 返回浏览器的数据只包含前端需要的安全字段。
- 修改返回结构前先查找所有前端消费点和历史持久化数据。
- 错误响应使用稳定、可展示的中文 `detail`；不得透传上游原始错误、密钥或连接信息。
- PATCH 只更新显式提交的字段，未提交字段保持原值。
- 时间使用明确时区；持久化和传输优先使用 UTC，展示转换交给前端。

## 3. 用户隔离与权限

- 会话、消息、收藏、工作台设置、常见问题和反馈操作必须按当前用户过滤。
- 读取、修改、删除和导出都要检查资源所有权，不能只在列表接口过滤。
- 删除接口应对不存在或不属于当前用户的资源返回安全结果，不泄露其他用户资源是否存在。
- 保持 Cookie、Origin 校验和已有登录限流策略，除非需求明确要求变更。

## 4. 问数与 SQL 安全

- 模型只生成受约束的查询计划，SQL 必须由程序编译。
- 所有筛选值使用绑定参数，不拼接用户输入。
- 保持 SQLGlot AST 校验、允许表/schema/函数限制和单条 SELECT 限制。
- 查询使用 analyst 只读连接、READ ONLY 事务、statement timeout 和结果上限。
- 新增指标时必须声明粒度、公式、允许维度、时间行为和比较逻辑，并增加独立数值核对。
- 百分比指标按业务公式聚合，不能平均分组百分比。
- 不跨不兼容事实粒度直接 JOIN；需要时先分别聚合或使用既有 UNION ALL 结构。

## 5. NDJSON 流

- 只发送真实可解释的阶段状态，不暴露或伪造模型内部思维链。
- 每个事件是一行完整 JSON，并以换行分隔。
- `status` 用于阶段，`analysis` 用于可审计步骤，`result` 是唯一最终消息。
- 成功、业务澄清、不支持、验证错误、系统错误和取消都必须持久化一致的消息状态。
- 客户端取消后要释放 advisory lock 和连接；异常路径也必须进入清理逻辑。
- 最终结果中的文字、图表数据、汇总值和执行审计必须来自同一次查询结果。

## 6. 数据库与迁移

- Schema 变更必须通过 Alembic，不在启动代码中临时修改生产表。
- 已发布迁移保持不可变；新增变更创建新版本。
- 新增领域表或列时同步更新 `app/catalog.py` 的中文业务说明和数据库 COMMENT。
- 初始化和迁移不得覆盖已有业务数据。
- 数据导入前检查目标是否已有数据，并核对逐表记录数。
- 不运行 `docker compose down -v`，除非用户明确要求删除整个容器数据库。

## 7. Python 实现

- 使用明确的函数和 Pydantic/SQLAlchemy 类型边界，避免宽泛字典在多层间无约束传递。
- 同步数据库工作不要阻塞异步事件循环；沿用线程池边界处理同步查询。
- 只捕获能够处理的异常。未知异常记录类型和追踪标识，对浏览器返回通用安全提示。
- 重试仅用于明确的瞬态外部错误；取消和业务校验错误不得重试。
- 日志不得包含密码、Cookie、完整 token、API Key 或不必要的用户敏感内容。

## 8. 验证流程

1. 查看 `git status` 并确认数据库目标不是生产环境。
2. 运行 `PYTHONPATH=backend .venv/bin/pytest backend/tests -q`。
3. 涉及数据库、权限、迁移或数值计算时，再运行数据库集成测试。
4. 涉及接口契约时，用真实请求核对状态码和响应结构。
5. 涉及流式问数时，检查事件顺序、最终持久化、取消和 advisory lock 释放。
6. 真实模型评估会消耗额度，只在任务明确需要时运行。
7. 在交付说明中写明测试数量、数据库环境和未验证项。

不要为了通过测试降低用户隔离、SQL 校验、只读权限、超时或结果限制。
