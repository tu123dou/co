# 架构与实施边界

## 请求路径

浏览器 → 同源 API → 登录身份和会话归属校验 → 精确词面匹配与 pgvector 语义召回 → 百炼自然语言解析 → Pydantic 查询计划校验 → 业务实体值校验 → 程序 SQL 编译 → SQLGlot AST 校验 → PostgreSQL 只读事务 → Decimal 指标计算 → 确定性文字、图表和取数依据。

执行进度通过 NDJSON 流返回；这是真实阶段状态，不展示或伪造模型内部思维链。每次回答保存数据版本、模型、用量、参数、SQL及耗时。暂不提供任意模型 SQL 执行。

## 代码与事务边界

后端采用模块化单体。`main.py` 只装配应用；`api/` 处理 HTTP 协议；`services/ask.py` 协调问数步骤；`repositories/` 管理应用事务和所有权；`presentation/` 生成展示内容；`query/` 分离编译、安全校验、执行、计算与 SQL 展示。接口与历史结果结构保持兼容。

问数准备事务写入用户问题；终态事务原子保存助手消息、执行审计、检索审计，并在成功时更新常见问题和追问上下文。终态写入再次按用户归属锁定会话行，已删除会话不重建。数据库故障无法保证结果保存时，返回安全错误并记录消息 ID。

应用写入池与只读查询池之外，增加独立会话锁池，避免模型等待占满鉴权和消息写入连接。同步数据库操作经工作线程执行；获取锁后结束事务，保留会话锁至请求结束。HTTP 请求依赖负责清理，取消清理与终态提交使用屏蔽取消的作用域；解锁失败时销毁连接，防止持锁会话被重复使用。

## 数据粒度

contract_items 是产品粒度的签约事实；revenue_entries/cost_entries 引用该明细。payment_entries 只引用合同。monthly_targets 的唯一粒度为 月×经营单元×产品线。不同事实分支使用 UNION ALL 再聚合，避免多对多连接导致重复累计。

十四个应用表包含账号、会话、审计、用户工作台设置、常见问题统计和语义检索。指标的可执行语义由版本管理中的 semantic.py 控制；metric_definitions 保存部署版本的业务说明。变更公式时需同时升级指标版本和历史口径展示，不能直接用新公式重写历史回答。

27张领域表的中文名称、用途、每行数据粒度和全部列语义由 `backend/app/catalog.py` 统一定义，并通过 Alembic 写入 PostgreSQL 的表、列 COMMENT。数据库连接器可使用 `obj_description` 和 `col_description` 原样读取；测试会阻止新增未注释的领域表或列。Alembic 自身的迁移版本表作为基础设施表单独注释。

## 语义召回

目录同步把指标、维度、表字段、标准实体和示例问法写入版本化文档，并由百炼 `qwen3.7-text-embedding-flash` 生成1024维向量。查询先做标题精确匹配，再以余弦距离做精确向量检索；当前约千级文档无需近似索引。达到数万分块并完成召回率基准后再增加 HNSW。召回结果和耗时写入 retrieval_events，便于评估命中率。

向量相似度不参与金额、同比、毛利率等计算，也不能直接决定 SQL。它只缩小模型看到的业务上下文。LlamaIndex 暂不引入，避免在已有受控计划链路外再增加抽象层；需要多数据源、复杂文档切分或混合检索编排时再评估。

## 执行控制

- 应用账号 app 为 schema 所有者，负责迁移及应用写入。查询账号 analyst 只有 analytics 的 USAGE/SELECT。
- SQLGlot 接受单条 SELECT，扫描整棵 AST，限制语句类型、表、schema及函数。真正的 SQL 只来自程序编译器，筛选值以绑定参数传入。
- 数据库每次开启 READ ONLY 事务，设置10秒 statement_timeout。分组最多500组，用户展示limit最多100。
- 每个用户同一时刻只允许一个问数请求，通过 PostgreSQL advisory lock 在多后端进程间协调。
- 中止浏览器请求会取消模型调用；已经在数据库执行的查询可能继续到完成或超时，同步工作结束后仍释放会话锁；模型等待期间断连则取消模型并保存取消状态。
- HTTP-only、SameSite=Strict cookie 认证；修改请求校验 Origin。JWT 有效期12小时。工作台设置、会话和收藏按登录用户隔离；普通用户仅能查看自己的反馈，超级管理员可查看全部反馈并更新处理状态与说明。
- 当前登录限流为进程内基础限流，适合单机第一版；多实例生产环境应在入口增加共享限流和完整审计。
- 模型返回原始上游错误及密钥不向浏览器透传。连接/超时/限流失败最多尝试3次；无效结构最多请求模型修正一次。

## 扩展方向

1. 接入真实数据库：保留同一查询计划，在数据适配层注册业务字段、维度和合法关联，不开放应用schema。
2. 扩充指标：声明粒度、公式、允许维度和测试基准；版本化迁移，不凭同名字段自动关联。
3. 语义目录增多后：基于离线评测调整召回条数、混合权重，并在必要时增加 HNSW 或重排模型。
4. 组织数据权限：在解析之前提供用户可见目录，并在编译器或数据库RLS中强制过滤。不能只依靠prompt限制。
5. 公开生产环境：HTTPS、备份恢复演练、共享限流、密码修改与账号管理、独立迁移任务、监控告警及并发压测。

## 已知限制

复杂筛选、逐笔财务流水、跨指标自由运算及因果推断不在第一版查询计划中。客户合同清单通过受控的合同维度查询，仍由程序编译固定SQL。反馈支持提交、筛选分页及超级管理员处理；处理结果不自动修改指标口径或历史回答。结果摘要为程序生成，模型仅负责理解自然语言。业务数据包含合同税率和应收核销口径，但不包含完整会计科目，不作为财务账套。
